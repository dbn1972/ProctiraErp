# Gap remediation — canonical ledger

## Single source of truth

`CANONICAL_LEDGER.csv` is the one authoritative record of every audit finding
(PRC id) and its current disposition. All status questions ("how many gaps are
left?", "is PRC-X closed?") are answered from this file and nothing else.

It is generated by `reconcile_ledger.py`, which collapses the historical
per-wave disposition CSVs (`PR2/PR3/PR4_*`, `w2_*`, `w3_*`) into one row per
PRC id, keeping the disposition from the **latest wave** that touched each id.

### Why the old counts kept changing

The same finding was re-dispositioned in successive waves, so each per-wave CSV
repeats ids from earlier waves. Summing rows across files double/triple-counted
and produced a different total in every report. Deduplicating by PRC id with
latest-wave-wins gives the true universe: **758 unique findings**.

## How to close a finding (process)

1. Fix only what the finding's acceptance describes (scope stays fixed).
2. Prove it: failing-first test for security / tenancy / privacy / finance /
   data-integrity findings; a passing regression test otherwise.
3. In `CANONICAL_LEDGER.csv`, set that id's `disposition` to `FULLY_CLOSED`
   and put the proof in the `evidence` column (test path, PR number, commit).
4. `PARTIAL` stays `PARTIAL` until its residual is actually done; never mark a
   finding closed beyond its evidence. `STALE`/`DUPLICATE` are recorded, not
   counted as remaining work.
5. Work in batches of ~10 (one branch, one PR to `main`, one review) per the
   `audit-gap-fast-mode` workflow rule. Do not create new per-wave CSVs.

The historical per-wave CSVs are kept for provenance but are no longer updated.
